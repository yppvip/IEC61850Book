GOOSE：从状态到二层事件帧

配置 → 信号 → 编码 → 字段 → 工程证据

本模块使用原创、脱敏、固定教学案例。页面只在本地切换示例和高亮字节；不读取用户抓包、不发送报文。XML 为保留引用链的部分模型，不等同于完整可投产 SCD、设备手册或标准原文。能解释本例不等于完成独立现场分析能力或符合性验证。

A. 这个报文是干什么的？

断路器位置变化后，发布IED把数据集状态提供给订阅IED用于联闭锁或状态交换。传统 GOOSE 直接使用Ethernet组播，EtherType=0x88B8，无IP/TCP、无逐接收端ACK；快速重传与稳定期重传帮助订阅端维持当前状态。报文到达不能单独证明出口逻辑或开关动作。

B. 从 XCBR.Pos 到 DataSet 与 GoCB

读取 本地原创部分 SCD：Demo/AP1/LD0/LN0/DataSet dsPos 第1个FCDA是 XCBR1.Pos.stVal [ST]（Dbpos），第2个是 Pos.q [ST]（Quality）；GSEControl gcbPos 引用 dsPos，confRev=1。GoCB 是运行时 GOOSE Control Block，SCL 的 GSEControl 是其配置声明。

<DataSet name="dsPos">
  <FCDA ldInst="LD0" lnClass="XCBR" lnInst="1" doName="Pos" daName="stVal" fc="ST"/>
  <FCDA ldInst="LD0" lnClass="XCBR" lnInst="1" doName="Pos" daName="q" fc="ST"/>
</DataSet>

网络侧 ConnectedAP@iedName=Demo、apName=AP1 → GSE@ldInst=LD0、cbName=gcbPos；Address给出目的MAC和数值APPID=0x1001。GSEControl@appID="DemoPos"是应用标识字符串，本例对应goID；它与Address/P[@type="APPID"]的16位数值不同。没有配置VLAN的本例以14字节Ethernet头演示，带单层802.1Q时业务头通常后移4字节，不能固定用本例偏移解所有帧。

C. 报文如何组成？

Ethernet目的/源MAC各6字节、EtherType2字节 → GOOSE固定头（APPID、Length、Reserved1、Reserved2各2字节）→ GOOSE APDU（Tag 61，BER长度与字段）。Length=8+APDU长度，不包含MAC头、VLAN、FCS或Ethernet填充。线上的最小帧填充不应计入APDU。

字段类型/长度（Value）变化条件或含义
gocbRef / datSet / goIDVisibleString，变长控制块引用 / 数据集引用 / 发布应用标识；不因每次重传改变
timeAllowedToLiveBER INTEGER，变长，毫秒订阅端可等待下一帧的时间；可随重传阶段变化
t / timestamp8字节UtcTime本次状态变更时间；不是每一重传帧的新发送时间
stNum / sqNumBER INTEGER，变长状态序号 / 同状态发送序号；新事件sqNum重置为0；回绕与重启不能简单当丢帧
test（早期基线）BOOLEAN，通常1字节历史8-1标签[7]；新解码器可显示simulation；与成员q.test及扩展头S位分别核对
confRev / ndsComINTEGER / BOOLEAN配置修订 / 需要配置指示；数据集成员重排是需复核修订的情况，运行值变化不是配置变更

allDataSEQUENCE OF Data，变长按DataSet声明顺序编码；成员可为基本值、结构或数组

XCBR.Pos 是 DPC 双点位置。0=intermediate-state，1=off（本例分位），2=on（合位），3=bad-state。不要用BOOLEAN示范这个stVal；若用布尔保护动作信号，应换用已核对的SPS/ACT等具体模型成员。

E. 从状态到教学报文，而非修改几个字节

  1. 应用层获得位置变化和品质，按模型更新Pos.stVal/q/t；本例dsPos只选择stVal/q，未选择Pos.t。
  2. 按两个FCDA确定Dbpos与Quality。Dbpos的BER位串Value首字节06表示6个未用位；Quality取13有效位，Value为03 00 00。若选择整个FCD，allData应按结构编码，不能继续套用两项标量布局。
  3. GoCB观察数据集的新状态，本例stNum 7→8、sqNum→0、顶层t变为新事件时间；成员q保持原值，confRev仍为1。
  4. 重传保持数据、stNum和事件t，sqNum增长；具体时间曲线由配置与实现决定。20/40ms是本例声明的示意，不是标准唯一时序或设备参数推荐。
  5. 按映射重新计算BER父长度、GOOSE Length及帧封装。长度跨127/255等阈值、序号增长时可能改变字节数与偏移，不能只定位一个值字节修改。

MinTime/MaxTime是配置线索，不足以独立还原每次发送时刻；订阅需看Inputs/ExtRef、接收能力和现场验证，参见 反向映射。

来源、版次与适用范围

版次与来源边界：以项目既有早期 IEC 61850-8-1 中文资料的传统 MMS/GOOSE 映射为起点，并参照公开解码器 ASN.1 定义核对结构；SV 采用明确声明的 9-2 八通道 INT32/Quality 教学布局。它不是跨版次唯一实现，也不宣称完整符合 9-2LE 或 IEC 61869-9。本地9-2为DL/T 860.92—2006扫描件，本次视觉复核PDF第16～17页（印刷第12～13页）表13/14的容器及基础类型；早期smpSynch为BOOLEAN，本例按较新版公开解码定义的0/1/2枚举解释，1表示local，不能混用。7-2扫描件未逐条核验。公开解码器是交叉核对资料，不能替代适用版次标准。

职责：IEC 61850-6 管配置与交换；7-2 定义 ACSI（Abstract Communication Service Interface，抽象通信服务接口）；7-3 定义 CDC（Common Data Class，公用数据类）；7-4 定义 LN（Logical Node，逻辑节点）及数据对象；8-1 将服务映射到 MMS/传统 GOOSE；9-2 定义 SV 以太网映射。ISO 9506 定义 MMS（Manufacturing Message Specification，制造报文规范）；ASN.1（Abstract Syntax Notation One）描述结构；BER（Basic Encoding Rules）将结构编码为字节。IEC 62351 安全扩展不在本例内。
