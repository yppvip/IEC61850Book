概论：体系、服务模型与对象建模

从系统功能、信息模型和抽象服务进入 IEC 61850 / DL/T 860。

1. 本章位置与阅读边界

本章按 IEC/TR 61850-1 的介绍与概述主题组织，采用原创图表和中文解释建立入门框架；不重印标准原文，也不替代项目规范、设备手册、一致性声明或现场试验。IEC 61850 的重点不只是网络报文，而是让不同设备围绕一致的信息模型和服务语义交换数据。

阅读主线：一次系统中的功能由逻辑节点组织；逻辑节点的数据对象通过 ACSI 服务被访问或交换；最后才由 MMS、GOOSE、SV 等具体映射承载。
系统与功能变电站、间隔、保护、测控
→
信息模型IED / LD / LN / DO / DA
→
ACSI 服务读取、控制、报告、发布订阅
→
映射与工程MMS / GOOSE / SV / SCL

2. 设备、间隔（Bay）与虚拟间隔

Bay（间隔）是一次系统中可独立组织、运行或控制的局部单元，例如线路、主变、母联、分段、电容器或电抗器间隔。它位于 Substation → VoltageLevel → Bay 的一次系统结构中；不是一台 IED、不是逻辑节点，也不天然等于一个柜体。一个 Bay 可跨多个一次设备、自动化功能与 IED。

对象回答的问题不可直接推出的结论
物理/一次设备现场有什么设备、位于哪条回路。不直接给出完整通信服务或 IED 数据路径。
IED哪台智能电子设备提供数据、控制或通信服务。设备名称不能单独证明业务功能。
Bay一次系统按间隔如何组织。不等于一台 IED 或唯一柜体。
虚拟间隔如何集中组织跨物理间隔功能。不等于实际新增的一次隔离边界。

3. 变电站自动化系统接口模型：IF1～IF10

IEC/TR 61850-1 用站控层、间隔层和过程层描述功能位置，以 IF 编号标记典型的逻辑信息交换。这些编号用于讨论和引用，不规定一根独立电缆、唯一网络或唯一协议：一个工程可把多个逻辑接口映射到同一网络，也可为性能、隔离和冗余分开实现。

接口逻辑含义
IF1间隔层与站控层之间的保护数据交换。
IF2间隔层与远方保护的数据交换；原概述列为范围外。
IF3间隔层内部的数据交换。
IF4过程层与间隔层的 CT/VT 瞬时数据，尤其采样值。
IF5过程层与间隔层的控制数据交换。
IF6间隔层与站控层之间的控制数据交换。
IF7站控层与远方工程师工作站的数据交换。
IF8间隔间直接数据交换，尤其快速功能如闭锁。
IF9站控层内部的数据交换。
IF10变电站设备与远方控制中心的远方控制数据交换；原概述列为范围外。

4. 功能、逻辑节点与物理节点

功能（Function）回答“系统要完成什么”；逻辑节点（LN）回答“把功能拆成哪些标准化信息与服务单元”；物理节点（PN，Physical Node）回答“这些 LN 在哪个物理设备/计算平台上实现”。用户常说的“物理接点”若指开入/开出端子或接点，则属于 I/O 与一次接线概念，不能与 PN 混同。

不要倒推：看到 PTOC 只说明存在过流保护相关模型；整定、配合、投退、出口、闭锁和实际接点仍需结合 DO/DA、逻辑图、SCD、装置资料与试验记录。

5. IED、数据对象（DO）与数据模型

IED 是提供自动化数据和服务的设备实体，其服务器模型常按 IED → AccessPoint → Server → LDevice → LN0 / LN → DO → DA 展开。DO（Data Object，数据对象）是 LN 中表达一类功能数据的对象，例如断路器位置、测量量或保护起动；它并不等于一个孤立数值。DO 的内部属性常由 CDC 与类型模板定义，读取或交换时还需区分功能约束（FC）、质量 q、时标 t、单位、设置和控制模型。

原创阅读路径：IED “BayCtrl_A” → LD “CTRL” → LN “XCBR1” → DO “Pos” → DA “stVal / q / t”
类型追溯：LN@lnType → LNodeType（DO 列表）→ DO@type → DOType（DA / SDO）
层级作用
IED / LDevice组织设备与逻辑设备，定位服务提供者。
LN / LN0组织标准功能单元；LN0 还承载 LD 公共功能。
DO组织一类功能数据。
DA / BDA给出状态、质量、时标或结构成员等可访问内容。
CDC / 类型模板定义典型结构和实际类型引用。

6. 服务模型与 ACSI（抽象通信服务接口）

ACSI（Abstract Communication Service Interface）为 IED 的逻辑设备、逻辑节点、数据与通信服务提供独立于底层通信技术的抽象视图。它不是可直接连接的“网口 API”，而是用于描述数据访问、非请求上送、控制、文件和发布订阅等服务语义的共同语言；具体映射才把这些服务落到协议栈与编码上。

服务类别边界提示
数据访问可访问与可写范围由模型、FC、权限和 IED 能力共同决定。
报告与日志须同时核对控制块、DataSet、触发项与缓冲能力。
控制服务成功不等于一次设备已安全动作；仍受闭锁、权限和现场条件约束。
GOOSE / SV发布、订阅、数据集和通信地址构成完整引用链，不能只看 MAC 或 APPID。

7. DL/T 860 建模方法

建模不是先给每个信号起标签，而是先界定系统功能和一次位置，复用标准 LN、DO、CDC 与服务，最后落实到 IED 能力、通信与 SCL 引用。下图是原创的学习与工程沟通流程，不替代厂商工具或项目交付流程。

  1. 界定范围：明确变电站、电压等级、Bay、一次设备、功能边界、性能和安全约束。
  2. 功能分解：以标准 LN 类表达测量、保护、控制、闭锁等功能。
  3. 定义数据语义：选择 DO、CDC、DA、FC，并说明质量、时标、单位、设置与控制语义。
  4. 分配实现与服务：依据 ICD/一致性声明，将 LN 分配至 LD/IED，选择报告、控制、GOOSE、SV 或客户端/服务器服务。
  5. 形成可追溯工程：在 SCL 中建立类型模板、DataSet、控制块、订阅和通信引用，进行结构、引用与能力校验。
继续阅读：IED 与数据模型 → 一次系统与设备角色 → 十分钟读懂 SCD。
