1. SERVER 的定义、语法和属性

SERVER 描述设备外部可见行为。所有 ACSI 模型属于服务器，但同一物理 IED 可有多个接入点、服务器模型或不同映射角色。服务器既能与客户通信，也能向对等订户发布信息。地址抽象 ServiceAccessPoint 的类型由 SCSM 定义，不直接等于一个 IP 地址。

SERVER {
  ServiceAccessPoint [1..n] : SCSM-specific
  LogicalDevice      [1..n] : LOGICAL-DEVICE
  File               [0..n] : FILE
  TPAppAssociation   [0..n] : TWO-PARTY-APPLICATION-ASSOCIATION
  MCAppAssociation   [0..n] : MULTICAST-APPLICATION-ASSOCIATION
  service GetServerDirectory
}
属性名类型 / 个数功能 / 条件SCD 位置与关键字
ServiceAccessPointSCSM 特定；1..n系统范围内寻址服务器；地址类型和内容由映射确定IED/AccessPoint@name；Communication/SubNetwork/ConnectedAP@iedName/@apName/Address。地址 P 字段按网络/映射核对
LogicalDeviceLOGICAL-DEVICE；1..n服务器包含的 LD 集合AccessPoint/Server/LDevice@inst，版本适用时核对 ldName
FileFILE；0..n服务器提供的文件对象IED/Services/FileHandling 是能力线索；无完整 FILE 目录 XML
TPAppAssociationTPAA；0..n运行时建立的客户/服务器关联Services/DynAssociation、Server/Authentication 仅提供线索；没有每条运行关联的 XML 实例
MCAppAssociationMCAA；0..n单向发布到订户的上下文LN0 发布控制块 + Communication 的 GSE/SMV；没有 MCAA 标签

参考文件：IED C_G1101X → AccessPoint S1 → Server timeout="30" → LDevice LD0、MEAS 等。timeout 是 SCL Server 配置属性，不是原表 11 SERVER 的第六个抽象属性。Authentication 是 Server 子元素，地址配置位于独立的 Communication 树。网络、设备和系统管理不由本部分完整规定。

2. Directory、GetDefinition 和 GetValues 区别

服务族回答的问题请求 / 返回SCD 静态对照
GetServerDirectory有哪些 LD 或文件？ObjectClass → Reference 列表Server/LDevice；文件目录需设备查询
GetLogicalDeviceDirectory这个 LD 有哪些 LN？LDReference → LNReference 列表LDevice/LN0、LN
GetLogicalNodeDirectory这个 LN 有哪些指定类对象？LNReference + ACSIClass → 实例名列表LN 下的 DATA、DataSet、RCB 等
GetDataDirectory这个 DATA 有哪些属性？DataReference → DataAttributeName 列表DOType/DA 及嵌套类型
GetDataDefinition属性结构、类型与 FC 是什么？DataReference → 完整嵌套定义LNodeType/DO → DOType → DAType/BDA
GetDataValues现在的值是什么？FCD/FCDA → 属性值SCD 定义与初值不能证明当前过程值

SCD 与在线目录都可帮助自描述，但二者证据不同：文件可能未更新，目录可能按客户视窗过滤。发现少了对象时，先核对版次、配置、视窗与查询类别，不直接判定设备模型不完整。

3. GetServerDirectory 请求和响应全表

该服务检索寻址服务器向请求客户开放的 LD 或 FILE 名列表。服务表中不另列访问点，不表示无需知道访问目标；关联/映射上下文已经确定服务器。

阶段 / 参数类型 / 域功能与条件例子 / SCD 对照
Request.ObjectClassLOGICAL-DEVICE 或 FILE选择目录对象类；不是让客户提交某个 LN 名选择 LOGICAL-DEVICE；静态对照 Server/LDevice
Response+.Reference[0..n]LD ObjectReference 或 FileName；文件名 VISIBLE STRING255服务成功，返回可见对象引用/文件名零项可以是成功空目录；不等于服务失败
Response−.ServiceErrorServiceError请求失败，返回原因class-not-supported、access-violation 等依实际失败情况
原创 ACSI 教学交互（不是 MMS 编码报文）：
已建立 TPAA，目标为 C_G1101X / S1 的 Server
Request:   GetServerDirectory { ObjectClass: LOGICAL-DEVICE }
Response+: { Reference: ["C_G1101XLD0", "C_G1101XMEAS", ...] }
另一请求可能返回：Response− { ServiceError: "access-violation" }

例中的 LD 名按源 SCD 与通常 IED 名+inst 规则构造；它不是实际抓取的设备响应，省略号也不是字面返回内容。GetServerDirectory 返回目录，不建立关联、不读过程值、不获取完整类型定义。实际 MMS 映射需查 服务映射。

4. 应用关联 AA：组成与使用

应用关联把信息交换双方及其上下文联系起来。本章模型包括关联类型和访问控制：TPAA 为双向面向连接的信息交换，MCAA 为单向发布上下文。可靠连接可以报告未及时交付的原因并实施端到端流控制；这不意味着客户端发出的电气动作一定成功。

特征TPAAMCAA
关系客户与服务器建立关联发布者与一个或多个订户
方向双向单向
服务形态确认请求响应与无确认通知均可单向无确认发布
典型应用目录、读写、报告管理、控制、文件GOOSE、GSSE、多播 SV
建立/结束Associate；Release 或 Abort按发布配置和每次报文上下文解释，不逐订户握手
关键边界Report 本身是无确认服务，底层可有可靠传输无逐订户确认，不据此断言业务方必已使用数据

服务确认与底层传输确认属于不同层次。运行关联不是 DataSet，也不是服务器 IP 地址本身。

5. 访问控制与服务访问视窗

虚拟访问视窗 Virtual Access View 是服务器对某个客户开放的对象、属性和服务集合。它既限制“看见什么”，也限制“可对它做什么”。一个对象在设备中存在，不保证每个客户能发现或写入它；隐藏必选属性不会取消设备实现该属性的要求。客户端也可实施额外限制，但服务器仍负责其访问控制。

约束对象例子SCD 可见程度
实例可见性A 看不到某 DATASCD 可列实例，但不保证 A 的运行目录相同
属性访问读允许，写拒绝FC 和类型帮助判断用途；不是完整权限策略
服务能力允许读，不允许 OperateServices 是能力声明，不等于某客户授权
运行状态对象被占用或当前模式不允许操作需运行关联、模式及状态证据
认证AuthenticationParameter 标识访问上下文Server/Authentication 为配置线索；无完整用户权限矩阵

原文将认证参数结构/内容及安全要求的实现交给 SCSM。空 Authentication 元素不能证明已启用密码、证书认证或加密，也不能反向证明没有任何访问控制。

6. TPAA 语法、属性与服务

TWO-PARTY-APPLICATION-ASSOCIATION {
  AssociationId          : SCSM-specific
  AuthenticationParameter: SCSM-specific
  services: Associate, Abort, Release
}
属性类型 / 值域含义与功能使用条件 / SCD
AssociationIdSCSM 特定；本部分不定义整数宽度或字符串长度区分某条应用关联；可在线交换或只在本地使用后续服务在相应上下文使用；不是 IED 名或 MAC
AuthenticationParameterSCSM 特定；结构/合法值由映射定义标识所需访问许可信息，不匹配时拒绝建立关联时传递；SCD Authentication 不保存本次参数
服务阶段和参数功能 / 使用时机失败 / 结束语义
AssociateRequest：ServerAccessPointReference、AuthenticationParameter；Response+：AssociationId、Result对特定服务器建立 TPAA失败返回 ServiceError；不匹配认证参数拒绝
ReleaseRequest：AssociationId；Response+：AssociationId、Result正常结束；已发服务在结束前完成，不再发新请求失败返回 ServiceError；不是立即丢弃所有请求
AbortRequest / Indication：AssociationId、Reason突然中止；可由关联双方或下层触发丢弃未完成请求，不再处理；不是正常成功响应式释放

Associate 的源表将否定字段写为 ServerError，紧随解释使用 ServiceError；本文按该处服务错误语义解释并保留写法差异。Result 表示关联管理操作结果，不是设备控制执行结果。

7. 正常操作与异常中止流程

关联中止后非永久数据集自动删除；URCB/USVCB 的关联保留按模型释放。BRCB 事件缓存和取代状态不能简单解释成“断线全部清零”；恢复需按各模型、设备能力及有效条目范围核对。

8. MCAA 功能、参数与发布订阅

MCAA 提供一个发布者向一个或多个订户的单向交换，携带足够上下文让订户解释数据。第 7.5 节类表唯一列出的属性是 AuthenticationParameter，类型和值域由 SCSM 确定；本部分不规定通用 AssociationId。
