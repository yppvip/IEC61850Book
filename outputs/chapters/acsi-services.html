ACSI 服务分类与功能全表

服务规定怎样访问、交换或操作模型对象，以及请求与结果怎样解释。

阅读位置与来源边界

上级：第 7-1 部分：原理与模型。按“概念 → 对象与属性 → SCD 证据 → 使用边界”阅读；本页是原创中文导读，不是标准原文或可投产配置。

1. 为什么需要服务

ACSI（Abstract Communication Service Interface，抽象通信服务接口）使客户端和 IED 围绕同一对象语义交互：发现模型、读值、改变允许改变的参数、请求控制、获得事件或样本、查询历史。服务是行为契约，定义对象引用、请求参数、响应和错误；SCSM 再定义它用什么协议消息承载。

交互方式角色典型服务目的
客户/服务器Client / Server发现、读写、操作、报告控制、日志查询、文件定向请求/响应与关联内通知
发布/订阅Publisher / SubscriberGOOSE、MSV/USV生产方发布，消费方订阅；样本/事件处理
时间同步时间源 / 使用者TimeSynchronisation统一事件和样本的时间参照

服务类名称不保证 IED 实现每一种服务。实现范围须读 PICS、MICS、PIXIT、SCL Services 与设备文档；SCD 未出现某控制块只证明该文件未声明，不能独立证明产品绝不支持。

3. 请求、响应和错误怎样读

信息功能例子
ObjectReference定位被访问对象LD_A/XCBR1.Pos；必须有明确服务器与 LD 上下文
FunctionalConstraint筛选属性用途读 ST 状态，读 MX 测量，访问 CO 控制
Request服务请求参数Operate 带命令值、origin、ctlNum、T、Test、Check 等
Response+服务请求按定义成功处理不保证整个电气动作已完成，需读控制状态机
Response− / ServiceError请求失败或不能处理权限、对象、参数、资源、选择资格或运行条件；具体错误枚举依模型/映射
Report / CommandTermination异步通知或最终控制结果与请求响应分开读取

例如查询读到 Pos.stVal=on，只说明该对象在返回时的状态值。要判断一次开关可信状态，还需 q、t、数据来源、质量策略及现场资料。控制否定响应也不能只看一个错误名字便断定是联锁：要定位错误阶段和适用检查。

4. 查询、报告、日志、GOOSE、SV 的区别

机制数据组织时机/节奏历史/恢复与约束
轮询 Read指定属性/数据集客户端请求可能遗漏两次读取之间的变化
URCB Report数据集触发或 GI/完整性周期不提供 BRCB 断线事件缓存
BRCB Report数据集触发和缓冲发送缓存有限，关注 EntryID、溢出与恢复
Log 查询由 LCB 记录的数据集条目先内部记录，后按范围检索本地循环存储/保留策略；记录与查询异步
GOOSE数据集状态值状态变化加重发机制接收方检查有效期、状态号、序列等；无逐订户确认
SV有序样本成员采样节奏连续性、同步、数值表示和品质；不自动补发丢失样本

日志和报告可用同一数据集，但控制块各自独立；报告成功接收不证明日志已留存。GOOSE 的 Test、NdsCom、质量和重发规则要与业务接受策略一起解释。

5. 能力声明与互操作

缩写英文用途
PICSProtocol Implementation Conformance Statement协议实现一致性声明：支持哪些模型、服务、选项
MICSModel Implementation Conformance Statement模型实现一致性声明：实现哪些 LN、DO、CDC 等
PIXITProtocol Implementation eXtra Information for Testing测试所需额外实现信息：参数、限制和行为说明
SCL ServicesServices capability description工程文件的能力声明，受 SCL 版本和文件完整性约束

互操作是不同设备围绕正确语义交换和使用信息的能力；可互操作不自动等于设备可直接互换。互换还涉及采集接口、性能、功能实现、整定、接线和工程配置。
