MMS：从对象到请求与响应

配置 → 信号 → 编码 → 字段 → 工程证据

本模块使用原创、脱敏、固定教学案例。页面只在本地切换示例和高亮字节；不读取用户抓包、不发送报文。XML 为保留引用链的部分模型，不等同于完整可投产 SCD、设备手册或标准原文。能解释本例不等于完成独立现场分析能力或符合性验证。

A. 这个报文是干什么的？

值班画面需要显示断路器当前分合位，客户端可以 Read 读取状态；持续遥信/遥测通常配置报告。MMS 承载 IEC 61850 客户端/服务器服务映射，不能把 MMS 等同于轮询，也不能把一次 Write 成功等同于断路器已经动作。

Service 是协议操作及其参数/结果约定。例如 Read 定义“访问哪些变量”和“每项返回值或错误”；Confirmed Request 中的服务选择 CHOICE 标签决定操作，Confirmed Response 给出对应结果。它不是可以随意填写的普通业务字段。invokeID 只在同一应用关联中配对请求与响应，不能跨连接全局匹配。

B. 从 SCD 对象到 MMS Variable

本例：IED=Demo，AP=AP1，LDevice@inst=LD0，无显式 ldName，因此示例 LDName=DemoLD0；LN=XCBR1；DO=Pos（DPC）；DA=stVal，FC=ST，bType=Dbpos。模型中“合位”编码2，映射到两个有效位10。

SCD Demo / AP1 / LD0 / XCBR1 / Pos / stVal [ST]
→ MMS domainID = DemoLD0
→ MMS itemID   = XCBR1$ST$Pos$stVal
→ Read Request invokeID=1
→ Read Response invokeID=1, AccessResult.success = BIT STRING 10 (on)

名称不是把任意工程字符串机械替换成“$”：先确定 LDName、完整 LNName（prefix+lnClass+inst）、FC 与属性结构。本例模型还把 stVal/q 放入 dsPos，供报告或 GOOSE 使用，但本例单变量 Read 不依赖它们。完整结构见 类型与 SCD。

C. 整体层次与常见服务

数据阶段层级：Ethernet（本例14字节）→ IPv4（20字节，实际按IHL）→ TCP（20字节，实际按DataOffset）→ TPKT（4字节，包含总长度）→ COTP DT（本例3字节）→ Session DATA（本例4字节）→ Presentation / PDV-list → MMS。建关联另有 ACSE AARQ/AARE、MMS Initiate；ACSE 不会在每一个 Read 帧重复出现。

本例假定已协商 MMS presentation-context-identifier=3，且每帧恰含一个完整TPKT。真实TCP可将一个TPKT切到多段、将多个TPKT合并；先做流重组再看MMS，不按抓包帧边界猜PDU边界。TCP/102只是一条筛选线索，未完成上下文验证不能认定都是MMS。

交互 / 服务在IEC 61850中的作用报文与注意点
Initiate Request / Response协商MMS最大PDU、并发未完成服务、服务支持等A8/A9 PDU；关联建立阶段，需要与ACSE/表示上下文一并检查
GetNameList发现域/命名对象/列表的目录Confirmed服务[1]；目录不是当前值，也不是SCD文件传输
Read读DO/DA、控制块或命名变量列表Confirmed服务[4]；VariableAccessSpecification选择变量列表或列表名
Write写可写数据、RCB属性、定值或控制结构Confirmed服务[5]；权限/FC/状态机和逐项错误仍有效
Report缓冲/非缓冲报告由服务器主动发出Unconfirmed PDU → InformationReport，无invokeID；看RptID、OptFlds、inclusion-bitstring、值与ReasonForInclusion
Control选择、操作、取消和结果语义ACSI Control不是一个名为Control的MMS服务；SBO读，SBOw/Oper/Cancel写；CommandTermination另核对
Confirmed Error / Reject服务失败或PDU处理拒绝与ReadResponse内每项AccessResult.failure不同；不能把三者混为一类

报告链：ReportControl → DataSet → 触发项 dchg/qchg/dupd/GI/周期等 → 使能后的运行时 RCB → InformationReport。inclusion-bitstring 选择本次包含的成员，不能假定每次总含全部信号；可选数据引用/配置版本按 OptFlds；报告分段还要看分段相关字段。SCD 不保存客户端实际使能状态。

D. 配对完整 Read Response

同一关联中 invokeID=1，对应一个访问结果。请求未要求 specificationWithResult，因此此响应不重复对象名；按请求变量顺序解释。成功值直接取 MMS Data 的 BIT STRING 标签，失败分支使用 DataAccessError。只读 stVal 的本例响应不包含 q/t，不应从值“2”推断品质或新鲜度。

E. 某个状态或测量值怎样进入数据区？

  1. 从 XCBR1.Pos.stVal 出发，沿 LNodeType → DOType 确认 DPC/Dbpos、ST、只读状态含义。
  2. 将访问对象映射为 domain/item，Read Request 只携带访问规格，不携带“想读到的值”。
  3. 服务端应用更新模型，编码 Read Response 的 AccessResult；分位位串为84 02 06 40，合位为84 02 06 80。若响应品质或时间也需要，须显式访问对应属性/结构。
  4. 改成报告时才沿 dsPos 成员顺序、brcbPos、OptFlds、inclusion-bitstring 组织 InformationReport；不能套用ReadResponse字节。
  5. 测量 FLOAT32 不是把十进制文本贴进报文：典型MMS浮点值1.0示意为87 05 08 3f 80 00 00（08是指数宽度，后4字节IEEE754）；单位/比例和原始/二次/一次值仍由模型决定。

客户端要控制断路器时访问适用的CO结构，按ctlModel、origin、ctlNum、T、Check、Test等规则完成选择/操作及结果确认。状态stVal是反馈，不是用普通Write改成“合位”的命令接口。继续阅读 控制模型、定值开发流程。

来源、版次与适用范围

版次与来源边界：以项目既有早期 IEC 61850-8-1 中文资料的传统 MMS/GOOSE 映射为起点，并参照公开解码器 ASN.1 定义核对结构；SV 采用明确声明的 9-2 八通道 INT32/Quality 教学布局。它不是跨版次唯一实现，也不宣称完整符合 9-2LE 或 IEC 61869-9。本地9-2为DL/T 860.92—2006扫描件，本次视觉复核PDF第16～17页（印刷第12～13页）表13/14的容器及基础类型；早期smpSynch为BOOLEAN，本例按较新版公开解码定义的0/1/2枚举解释，1表示local，不能混用。7-2扫描件未逐条核验。公开解码器是交叉核对资料，不能替代适用版次标准。

职责：IEC 61850-6 管配置与交换；7-2 定义 ACSI（Abstract Communication Service Interface，抽象通信服务接口）；7-3 定义 CDC（Common Data Class，公用数据类）；7-4 定义 LN（Logical Node，逻辑节点）及数据对象；8-1 将服务映射到 MMS/传统 GOOSE；9-2 定义 SV 以太网映射。ISO 9506 定义 MMS（Manufacturing Message Specification，制造报文规范）；ASN.1（Abstract Syntax Notation One）描述结构；BER（Basic Encoding Rules）将结构编码为字节。IEC 62351 安全扩展不在本例内。

可选在线追溯（离线阅读不依赖链接）：IEC 标准体系目录 · ITU-T X.690 BER 规则 · Wireshark MMS ASN.1 · GOOSE ASN.1 · SV ASN.1。
