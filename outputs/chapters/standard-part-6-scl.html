标准文库 · DL/T 860.6 / IEC 61850-6 导读

第 6 部分：SCL 与 IED 通信配置描述

从 SCL 文档结构、对象引用和通信配置，建立 SCD 的可追溯阅读方法。

1. 本章位置与阅读边界

本章围绕《变电站通信网络和系统 第 6 部分：与变电站有关的 IED 的通信配置描述语言》的主题，以原创说明归纳 SCL（Substation Configuration Language）的对象、约束和工程阅读方法。它解释配置文件如何表达模型和引用，不重印标准原文，也不替代项目规范、厂商 ICD、工具校验或现场试验。

阅读主线：SCL → IED / Substation / Communication / DataTypeTemplates → 数据或一次对象引用 → 工程校验。名称、MAC、APPID、私有扩展均不能单独证明实际业务含义。

2. SCL、SCD 与工程文件

对象用途不应误解为
SCLXML 语言与文档结构规则，承载模型、通信、一次系统和类型模板。某一个唯一的工程交付文件。
SCD系统配置描述；汇聚全站 IED、通信网络、一次系统和工程引用。已经可直接下装每台 IED 的唯一文件。
ICD / CID分别面向 IED 能力声明与已配置 IED 的配置/交付边界。可替代全站通信和订阅核对。
SSD / SED / IID服务于系统规格、系统交换、IED 实例/能力的阶段性交换。所有工具或版次均以完全相同方式支持。

“地址”要分层：IED@name、AccessPoint@name、LDevice@inst、LN@prefix/lnClass/inst、DO/DA 是模型对象引用；IP、MAC-Address、APPID、VLAN 是网络通信参数。两者有关联，但不是同一个地址。

3. SCL/SCD 的顶层结构与每部分功能

组成部分常见子项功能与核对要点
HeaderHistory、版本、工具标识记录文档标识和演变线索；不是运行状态，也不能代替受控变更记录。
CommunicationSubNetwork、ConnectedAP、GSE、SMV、Address描述网络接入和发布侧网络参数；要与 IED 内控制块及接收侧输入共同核对。
SubstationVoltageLevel、Bay、ConductingEquipment、LNode表达一次系统组织和功能位置；不是完整单线图或施工图。
IEDAccessPoint、Server、LDevice、LN0/LN表达装置逻辑模型、数据集、控制块、输入和实例化值。
DataTypeTemplatesLNodeType、DOType、DAType、EnumType给模型数据提供类型定义；type 是类型链，不是运行值。
Private厂商或项目扩展需保留来源、命名空间和工具兼容性；不可套用标准语义推断。

4. 常用属性：它们是否构成“地址”

属性/元素典型位置含义是否为地址的一部分
name、iedName、apNameIED、ConnectedAP设备与接入点工程标识，用于跨区匹配。是模型/通信引用键的一部分；不是 IP 或 MAC。
inst、prefix、lnClassLDevice、LN、LNode、FCDA/ExtRef区分逻辑设备和逻辑节点实例/类别。是对象引用路径的一部分。
ldInst、lnInst、doName、daName、fcFCDA、ExtRef把引用细化至 LD、LN、DO、DA 和功能约束。是数据对象引用的组成；不等于网络地址。
typeLN/DO/DA 定义或实例指向类型模板 ID 或通信类型。否；它决定结构/语义，不定位通信端点。
desc多处人可读说明。否；可空、可变，不能作为可靠匹配键。
IP、MAC-Address、APPID、VLANCommunication/Address承载网络配置和流识别参数。是网络侧参数；不能反推业务对象。

5. 对象和信号说明：图 5 IEC 61850-7-2 信号名元素

信号名元素由上到下缩小范围：逻辑设备 LD → 逻辑节点 LN → 数据对象 DO → 数据属性 DA（必要时继续到 BDA）→ 功能约束 FC。工程文件中不一定以单一 XML 属性完整写出，而可能分散在 FCDA、ExtRef、类型模板和实例值中。

所给 SCD 可从 DataTypeTemplates 中大量出现的 LNodeType、DOType、DA 定义入手，再回到 IED 的 LDevice/LN 实例和 DataSet/FCDA。为保护工程信息，本章不公开原文件中的站名、设备名、IP 或私有标识；图中名称均为脱敏结构示例。

6. 图 6：采用功能命名的信号名元素

功能命名用标准 LN 类和 DO/DA 表达“测量、保护、开关、闭锁、控制”等功能语义；prefix 与 inst 区分同类实例。它不是把现场端子、屏柜或厂家变量名直接塞入信号名。

元素示例（原创）回答的问题仍须补充的证据
LN 类MMXU、XCBR、PTOC这是测量、断路器还是过流保护类功能？IED 能力、LN 类型、项目功能分配。
DOA、Pos、Op功能中是哪一个数据对象？CDC/DOType 定义和实际实例。
DA / FCstVal[ST]、ctlModel[CF]访问状态、配置、控制还是测量？DA 类型、取值、权限和服务模型。
desc工程说明文字帮助人阅读什么？可能缺失或变更，不能作为唯一机器匹配依据。
工程现象边界：同名 Pos.stVal 出现在 DataSet、GOOSE 或 MMS 报告中，只说明该模型项被配置为交换候选；是否对应某一实际断路器、是否已动作，必须结合 LNode 关联、控制/反馈链、质量、时标和现场条件验证。

7. 8.6 变电站描述：Substation 视图

Substation 视图以一次系统为中心，常见层级为 Substation → VoltageLevel → Bay → ConductingEquipment / PowerTransformer / Function → LNode。LNode 把一次位置或功能位置关联到 IED 内某个 LN；它不复制 LN 的全部数据，也不等于一一对应的物理设备。

该 SCD 的实际结果：检索未发现 Substation、VoltageLevel、Bay 或 LNode 元素。因此本文件可用于详读 IED、通信、数据集、外部引用和类型模板，却不能单凭自身还原一次电压等级、间隔或一次设备关联。若工程需要 8.6 的完整追溯，应补充含一次系统视图的 SCD/SSD、系统图或受控设计资料；不能依据 IED 名称、IP 或厂商描述推断。

当文件具备该视图时，阅读顺序是：定位 Substation 与电压等级/间隔；读取 LNode@iedName、ldInst、prefix、lnClass、lnInst；再到同名 IED 下验证 AccessPoint → Server → LDevice@inst → LN；最后追溯 LN 类型及数据集/通信。缺失关系标为“待项目资料确认”。

8. IEDRef、SecAPRef 和 ExtRef

名称功能何时使用阅读提示
IEDRef在需要指向另一个 IED 的上下文中，标识被引用 IED。系统模型或功能关联需要跨 IED 指代时。它本身不是 GOOSE/SV 订阅的充分证据；要看父元素与关联属性。
SecAPRefSecurity Access Point Reference，安全访问点/安全相关接入引用的结构锚点。采用相应安全建模、需要关联安全访问点时。精确适用条件取决于 SCL 版次、文件模式和工具支持；缺失不能证明未实施安全措施。
ExtRef接收 LN 输入的外部数据引用，携带源 IED、LD、LN、DO、DA、FC 等定位信息。GOOSE、SV 或外部数据输入完成工程绑定时。需与发布端 FCDA/DataSet、控制块及 Communication 的 GSE/SMV 形成闭环。
LNode一次系统位置对 IED 内 LN 的引用。变电站描述关联功能与一次设备/间隔时。它不是网络订阅，也不是数据集成员。

对该 SCD 的实际检查应以是否显式出现元素为准。未出现 IEDRef 或 SecAPRef 时，只能得出“文件未采用该表达”，不能推断未配置跨 IED 功能或安全控制。

9. 逻辑名转换为短地址

这是模型到具体通信实现的映射能力：较长、分层的逻辑对象名称可映射成通信协议或设备内部使用的短标识，以降低实现开销或兼容既有系统。它不改变 LN → DO → DA 的标准语义，也不会让业务含义变得可由短地址猜出。

观察层可能现象正确解读
工程模型仍可按 LD/LN/DO/DA/FC 追溯标准对象。工程人员应以模型路径和类型定义核对语义。
协议/设备实现读写或传输中使用短变量名、索引或对象名。短地址是映射结果；生成规则、稳定性和访问方式取决于实现与一致性声明。
变更后模型或映射变更可能使客户端/网关取数失败或读取错误对象。应做映射、互操作与回归验证，不能把“通信可达”当成语义正确。

10. CtlMode / ctlModel、控制 CDC 与属性

工程中常将“控制模式”泛称为 CtlMode；在 IEC 61850 数据模型中，更常见且可在 SCD 中追溯的是控制 CDC 的 ctlModel 数据属性（通常 FC 为 CF）。它说明控制服务采用何种基本交互模型，不表示设备已获授权、闭锁已解除或一次设备必然动作。所给 SCD 的类型模板中可见 ctlModel 枚举定义；具体对象实例值仍须沿 DOI/DAI 与类型链核对。

概念典型 CDC 角色常见属性/服务工程含义
Status（状态）SPS、DPS、INS、MVstVal、q、t表达状态/测量及质量、时标；不是命令。
Controllable（可控）SPC、DPC、INC、ENC、APCctlModel、Oper、SBO、Cancel具备控制对象结构；实际可控仍受权限、模式、闭锁和设备实现限制。
Command（命令）控制 CDC 的服务视图操作值、ctlNum、origin、检查/同步参数等客户端提出的控制请求；成功响应还需由状态/反馈和现场条件复核。
ctlModel 典型枚举含义阅读边界
status-only仅状态，不提供控制模型。不能从此对象发出常规控制服务。
direct-with-normal-security直接操作，常规安全检查语义。“直接”不等于绕过闭锁、权限或设备保护逻辑。
sbo-with-normal-security先选择、后操作的常规安全模式。选择超时、并发控制与来源校验须看 IED 实现。
direct-with-enhanced-security直接操作，增强安全语义。具体参数和支持能力需看一致性声明。
sbo-with-enhanced-security选择后操作，增强安全语义。不可据名称推断现场安全机制已完整部署。

11. 基于 DO 的 CDC：高频属性、取值与功能

qST/MX；Quality有效性、来源、测试、阻塞、溢出等质量位组合质量不是单一“好/坏”布尔量；位语义按类型与版次核对。
