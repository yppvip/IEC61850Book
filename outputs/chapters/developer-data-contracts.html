哪些软件经验可复用，哪些类比需要限界

熟悉的概念可用于理解类比的边界
类、实例与结构体LN/DO/DA 与 LNodeType/DOType/DATypeCDC 定义领域语义与属性约束，不能仅按同名字段或 JSON 结构合并。
外键与依赖图FCDA、类型 ID、ExtRef 的引用追踪引用存在只证明模型关系，不证明订阅配置已下载或现场回路正确。
发布订阅 / 事件GOOSE、报告和输入订阅不同服务的重传、缓冲、触发、接收判断与失效处理不同，不能套统一消息队列承诺。
RPC / 状态机控制请求、选择、操作、终止返回值和物理反馈分层；不可承诺“请求成功=断路器完成动作”。
版本化 SchemaSCL 命名空间、版次与工程修订根命名空间字符串不足以区分全部模型/服务能力；还需版本、修订、命名空间与设备声明。

建议在应用中保存的完整测点语境

以下是原创应用层记录建议，不是 IEC 61850 标准 JSON，也不是要求每个数据对象都有这些属性。按实际 CDC 和服务记录适用项，明确原始值与派生值。

{
  "objectReference": "LearnIEDMEAS/MMXU1.A.phsA.cVal.mag.f",
  "fc": "MX",
  "value": 300.0,
  "unit": "A",
  "valueBasis": "primary RMS; confirmed by engineering map",
  "quality": {
    "validity": "good",
    "test": false
  },
  "sourceTime": "original source timestamp",
  "timeQuality": "preserved from source",
  "receiveTime": "application receive timestamp",
  "freshness": "evaluated by application policy",
  "engineeringRevision": "teaching-R1",
  "evidence": "type chain + signal map; physical binding pending"
}

LearnIEDMEAS 是本例假定的 LDName；对象引用按 LDName/LNName.Data... 组织，不把 IED、LD 都当作斜杠目录。实例与 LDName 构造规则应由 SCL 和适用版本核对。本例数值读取相量幅值的浮点成员，q/t 按相应结构化对象关联；quality 为节选，不能用它覆盖完整 Quality 字段。

valueBasis、freshness、engineeringRevision 是建议的应用元数据；单位、变比、参考方向从工程证据确认，不能凭对象名自行补齐。

失效处理：不把观测缺失改写为物理状态

遇到的现象合适的处理方向常见错误
连接断开 / 数据过期保留最后值并明确失效原因与接收时刻，按对象和应用策略判断新鲜度把超时自动改为 0、分闸或正常。
GOOSE 重传或重复接收依据控制块、状态/序列号及接收状态处理；结合生存时间判断失效每收到一帧都创建一次新业务跳闸事件；把链路重传当作物理重复动作。
报告重连 / 缓冲补传核对 BRCB/URCB、EntryID、缓冲溢出和 GI/完整性信息承诺永不漏事件，或把补传到达顺序当作源事件顺序。
测试/取代/品质变化保留来源和品质，按服务与装置规则区分运行、测试和取代“有值就可用”；把 Quality.test 与 GOOSE simulation、LN.Mod 混为一位。
控制结果未知保存请求关联、状态与终止信息，核对新位置及品质，走业务决策超时立即无限重试，或提前把界面位置改为目标值。

详细属性与接收机制回查运行模型、通信与过程层和安全与测试边界。上表是应用设计方向，不是替代协议状态机的伪实现。

从“解析成功”到“工程成立”有几层检查

  1. 语法层：XML 是否可解析，字符编码和命名空间是否正确。
  2. 模式层：对应版次的 XSD 是否通过；通过仍不保证语义和工程完整。
  3. 引用层：实例、类型、FCDA、DataSet、控制块和外部订阅能否正反追踪。
  4. 语义/能力层：CDC、FC、枚举、单位、服务配置是否符合指定基线、设备能力与工程规范。
  5. 交付层：源文件、修订、工具导入导出、设备配置版本与变更记录能否对应。
  6. 现场功能层：实际接线、功能逻辑、时序、网络性能与受控试验结果是否满足要求。

配置阅读工具最多证明它实际检查到的层次。对于未检查的项应写“未验证”或“证据缺失”，不要把上游通过等价为现场通过。IEC 官方将语义、SCL 和通信作为相互配合的部分，参见 IEC 技术原理。

网络工程、权限和变更也是数据的一部分

IP/MAC/APPID/VLAN 用于连接与流量识别，不承载完整业务含义。VLAN 逻辑隔离也不等同于认证、加密或访问授权。PRP/HSR 等冗余提高特定故障下的可用性，但不代替业务去重、告警和一致性检查；两网、设备双配置与应用主备须分别分析。

安全工程可继续研究 IEC 62351、账户权限、时间源、工程访问及审计；具体方案按项目要求和设备支持核对。本库不配置在线服务或设备。变更应保存修改对象、影响订阅、配置修订、回退依据与复核记录，详见工程实践与变更管理。

自检：两种“正确”之间还缺什么

两个同名 stVal 可以按字段名合并吗？ · 展开参考答案

不能。先按对象引用、DO 的 CDC、DA 类型、FC、枚举、版次与测点绑定确认语义。断路器位置、告警状态和保护动作都可能有 stVal，却不是同一个业务类型。

为什么应用还要有 freshness，q=good 不够吗？ · 展开参考答案

q 是源对象的品质表达；应用在断链后仍可能缓存最后一次 good。新鲜度反映当前接收和服务状态，需要独立保存，不能直接伪造标准 q 位。
