1. 先定义“信号”再谈数量

不存在适用于所有MMS、GOOSE、SV的一个固定“最少/最多信号数”。字段整数范围、ASN.1列表可编码范围、有效服务要求和设备允许配置是不同约束；“语法能编码空列表”不能推出“工程应发布零信号”。本模块使用非空数据集；不虚构一个跨协议的数值下限。

协议这里的计数对象最小/最大该怎样回答
MMSRead请求变量数、AccessResult项数；Report本次包含成员数及结构内叶子依服务语义、协商PDU、列表/结构/分段与设备限制；没有一个固定全局信号上限/下限
GOOSEnumDatSetEntries是DataSet顶层成员数；allData一项可能是结构/数组编码可表示的整数不等于可装入单Ethernet帧的成员数；有效发布与空DataSet支持按版本/设备核对
SV每ASDU的配置成员、通道值/q对；noASDU是聚合组数八通道非标准全局固定数；ASDU计数范围也不是信号数量上限；须核对配置文件/映射与实现

本例GOOSE有2个标量FCDA（位置与品质），工程上描述1个位置反馈。SV有16个标量FCDA组成8通道，一帧含1个或2个ASDU；GOOSE中若把整个ST/FCD放成一个成员，内部stVal/q/t是多个叶子。DataSet成员数不能直接叫“业务测点数”。

以常见未扩展Ethernet的1500字节MAC客户数据为例，它不是整帧含MAC/FCS的长度。单层VLAN增加MAC头开销，是否仍保留1500字节客户数据取决于实际链路能力；不能把1500随意减去14或18两次。MMS的“一个PDU”与“一个Ethernet帧”必须分开问，TCP分段不等于MMS应用报告分段。巨帧/多标签/安全扩展须另算，不是默认解决方案。

3. 可复算的 GOOSE 容量算例

限定为本例短引用、所有头字段及计数保持同样长度、无安全扩展，每成员均为Dbpos标量。每项编码84 02 06 xx占4字节。案例原allData两项合计9字节（Dbpos4+Quality5）。令h(L)=2，当L<128；h(L)=3，当128≤L≤255；h(L)=4，当256≤L≤65535，它是本例单字节Tag加BER Length的头长。

N = 假设的Dbpos标量成员数
B = gocbRef…numDatSetEntries这些头字段的总编码长度（numDatSetEntries需按N更新）
D = 4 × N
A = B + h(D) + D             # APDU Value长度
GOOSE客户数据 = 8 + h(A) + A
要求：8 + h(A) + A ≤ 本链路允许客户数据；还须满足设备/配置约束

实际生成的本例GOOSE帧见下表：帧长减14即客户数据长度。以N=100测试时，allData Value=400字节，h(D)=4；numDatSetEntries=100仍占1字节值，但到128必须增加整数编码字节。本例N=100时B=85，A=85+4+400=489，客户数据=8+4+489=501字节，低于声明的1500预算；这只是满足本算例长度条件，不证明设备支持100成员。不要将(1500−8)/4向下取整就当最大值：漏掉引用、计数、allData与外层BER头，还未核对装置能力。

4. SV 的具体网络预算

本例单ASDU中svID等固定字段编码共22字节，seqData是2字节Tag/Length+64字节值；ASDU Value=88，ASDU整体=90。一个ASDU时：seqASDU=2+90=92；noASDU=3；SavPdu Value=95、整体=97；再加8字节固定头，客户数据105；加14字节Ethernet头，帧为119字节（无FCS）。下面以构建结果为最终算术核对；若前文参数改动，必须同步重算。

在50Hz、每周波80样本、一个样本组/ASDU的声明下，单ASDU每秒4000帧，两ASDU可为每秒2000帧；这里只是理想聚合算术，不决定真实时延/发送节奏。估算线上占用还需加FCS4、前导码/SFD8、帧间隙12及适用VLAN/冗余开销。正确做法是按类型和实际配置精算，再查看设备文档的支持限额与工程预算；本站不提供通用推荐“合理信号数”。

5. MMS 不能从 MTU 得出服务信号上限

本例Read一个Dbpos的完整请求与响应长短不同：请求含变量名与访问规格，响应含结果值。按同样变量数量，字符串长度、结构/数组、可选字段、访问错误和BER长度阈值都会改变PDU。应先确认Initiate协商的最大MMS PDU、设备单次访问数量及报告/RCB限额，再按当前服务和实际编码计算。

TCP负责字节流分段/重组，因此一个MMS PDU可跨多帧；“最多多少信号”不能只用1500除以单值宽度。报告只选部分成员且可能应用分段，也不等于任意超大报告总能被对端支持。SCD声明、设备能力、当前运行时协商及具体服务结果需要共同查证。

来源、版次与适用范围

版次与来源边界：以项目既有早期 IEC 61850-8-1 中文资料的传统 MMS/GOOSE 映射为起点，并参照公开解码器 ASN.1 定义核对结构；SV 采用明确声明的 9-2 八通道 INT32/Quality 教学布局。它不是跨版次唯一实现，也不宣称完整符合 9-2LE 或 IEC 61869-9。本地9-2为DL/T 860.92—2006扫描件，本次视觉复核PDF第16～17页（印刷第12～13页）表13/14的容器及基础类型；早期smpSynch为BOOLEAN，本例按较新版公开解码定义的0/1/2枚举解释，1表示local，不能混用。7-2扫描件未逐条核验。公开解码器是交叉核对资料，不能替代适用版次标准。

职责：IEC 61850-6 管配置与交换；7-2 定义 ACSI（Abstract Communication Service Interface，抽象通信服务接口）；7-3 定义 CDC（Common Data Class，公用数据类）；7-4 定义 LN（Logical Node，逻辑节点）及数据对象；8-1 将服务映射到 MMS/传统 GOOSE；9-2 定义 SV 以太网映射。ISO 9506 定义 MMS（Manufacturing Message Specification，制造报文规范）；ASN.1（Abstract Syntax Notation One）描述结构；BER（Basic Encoding Rules）将结构编码为字节。IEC 62351 安全扩展不在本例内。
