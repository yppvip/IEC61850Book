LD 是逻辑设备分组，DataSet 是对已有数据的有序引用集合。数据集不是新的 LN，也不会复制出一套保护算法。先按 IED → AccessPoint → Server → LDevice → LN0/LN → DataSet → FCDA 找到声明，再反向查哪些控制块使用它。

PTRC.Str 表达起动相关信息，PTOC.Op 表达过流功能动作信息，PTRC.Op 是保护跳闸调理相关的动作信息。StrBF 在本例类型中存在且为 ACT，其具体功能及扩展依据须回查模型说明，不把该名字当作所有 PTRC 的必备 DO。三个 PTOC 实例也不能仅凭编号认定为Ⅰ、Ⅱ、Ⅲ段。

从数据集到报告，再区分跳闸出口

  1. 定位集合：本例概念引用为 DemoProtectionPROT/LLN0.dsTripInfo，其他 LD 下的同名集合是不同对象。
  2. 查引用者：ReportControl@datSet 将报告与集合关联，本例是 BRCB。不能把任意 dsTripInfo 都认作 GOOSE 发布集。
  3. 确认运行控制块：SCL 声明与客户端所见 RCB 实例名还涉及 ReportEnabled、索引和实现。核对 DatSet、ConfRev、RptEna、TrgOps、BufTm、IntgPd，不能将模板短名当成全部运行实例名。
  4. 解释报告：先核对 DatSet/ConfRev 和目录版本，再依据 inclusion 位定位原始成员序号，按对应类型展开，结合 reason-for-inclusion、品质和源时标阅读。变化报告通常只含部分成员；使能报告不意味着必然立即上送初始全量。
  5. 追出口：另查实际 GSEControl 的 datSet、成员、Communication/GSE、接收端 Inputs/ExtRef，以及设备内部逻辑、压板和执行反馈。本例报告集不能替代这条证据链。

保护动作信息上送 ≠ 出口 GOOSE ≠ 断路器已经分闸。起动、功能动作、出口、智能终端执行、XCBR 位置反馈和 SOE 时间是不同证据，Op.general=true 不足以证明一次设备完成动作。

三道自检题

两个 IED 的 dsTripInfo 能共用序号表吗？

先核对完整身份、成员顺序、粒度、类型与版本。短名相同不足以证明结构相同。

本例第一个 FCDA 能直接按布尔值读取吗？

应先按 ST 展开 ACD 结构，取指定 general 等属性，并结合 q、t，不能将整个结构当 BOOLEAN。

Op=true 是否证明出口和分位都正确？

只是一项报告证据；出口发布、订阅、内部逻辑、执行和位置反馈须分别查证。
