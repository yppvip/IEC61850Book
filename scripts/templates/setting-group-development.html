修改定值与切换定值组：通信流程与开发实现

从 SGCB 和 SG/SE 视图，走到客户端状态机、服务端提交、异常恢复与两网适配。

1. 阅读位置、已有内容与版本

上级：工程应用 · 给开发人员的数据契约与工程边界。前置阅读：SP、SG、SE 与定值 CDC、定值组抽象模型、对象引用与 MMS 名称。

现有知识库有定值组的属性、六类服务和缓冲区模型，本页补齐可供开发人员参考的完整通信闭环。修改某组参数与把某组投入运行是两个请求：编辑非激活组后确认，不会自动切到该组；编辑当前激活组后确认，按适用版本语义可重新激活更新值，不能把确认理解成始终只保存、不影响运行。[S1、S4]

本页为静态开发参考。流程图、数值、伪代码均为原创脱敏教学示例，不等同于可投产程序、设备手册、标准原文或现场验收。本站没有设备连接、报文发送、上传或定值下装功能。

版本：本站旧章节基线为 DL/T 860.72—2004 / IEC 61850-7-2:2003；本页以 7-2 Ed2 服务语义串联流程，并标注 Ed2/Ed2.1 的预约和恢复问题。服务名称、可选属性及错误映射按项目采用的 7-2、8-1 版次、TICS、PICS、PIXIT 核对，不把新版本选项当成旧设备必选项。资料核对日期：2026-10-17。

2. 区分三种业务操作

用户意图协议操作完成证据
修改不采用定值组的普通参数按模型和权限读写 FC=SP 的可写属性；不强行套 SGCB写响应、读回值、设备定义的生效条件
修改第 k 组的一项或多项定值SelectEditSG(k) → 写 SE → 读回 SE → ConfirmEditSGValues提交应答与提交后组内容核对；编辑回显不等于已保存
将第 k 组投入运行SelectActiveSG(k) → 读 SGCB → 读 SGActSG=k，运行 SG 值与目标快照一致；LActTm 作辅助证据

SP 是功能约束，不表示所有定值都直接写 SP。SGCB 本身映射在 SP 下，组内待编辑参数用 SE；SG 是激活组视图，不能写 SG 代替写 SE。SelectEditSG 也不是控制模型的 SBO，不能用 SelectWithValue / Operate 替换。[S2、S3]

3. SGCB、引用与三个值域

定位顺序：IED/访问点/服务器 → 完整 LDName → LLN0.SGCB → 该块管理的 LN 定值对象 → 属性及 FC。基线中一个 LD 的 SGCB 位于 LLN0；跨 LD 关联另核采用版本的层级规则和设备说明，不能从 IED 名推断整机所有组一起切。

SGCB 属性语义 / 类型开发用途
NumOfSG组数，INT8U；普通组号 1..NumOfSG读取能力；不能通过写它动态新建组；特殊虚拟区另核规约
ActSG激活组号，INT8U经 SelectActiveSG 切换；SCL actSG 只是配置初值
EditSG编辑组号，INT8U；0 为未选组选组成功后才访问 SE；非零不证明本关联拥有预约
CnfEdit确认编辑，BOOLEAN 命令属性写 true 触发提交；不要求捕获一个持久的 true
LActTm最近激活时间，TimeStamp结合 ActSG、SG 核对，不能单凭时间判定目标值生效
ResvTms预约时间，INT16U，秒；Ed2 可选0 为当前未预约；缺失不等于没有锁或无限时间。Ed2.1 中读值为倒计时还是配置时长需核 PIXIT，不能照搬 BRCB 写法。[S4、S5、S8]

教学设备完整 LDName 为 DemoIEDPROT，ASG 对象 PTOC1.StrVal，叶属性 setMag.f。组号不编码进这条路径，由 EditSG 决定 SE 对应哪组。实际设备是否存在该 LN/DO、采用 f 还是 i，应沿实例和类型定义确认。

5. 前置准备：能力、权限与变更计划

  1. 固定标准版次、项目规约、设备型号和固件版本；核对 PICS 服务支持、PIXIT 定值行为和 TICS 修订采用情况。
  2. 解析 SCL 的 Services/SettingGroups、LDevice/LN0/SettingControl 以及 LN/DO/DA 类型与 FC。SGEdit、ConfSG 及 resvTms 分别描述编辑、配置和相应能力；配置初值不能证明当前值或在线写权限。[S5]
  3. 建立关联后读取实际模型及 SGCB。远方/就地、允许修改条件、权限与组间联动按已核实对象和规则处理，不猜对象名。
  4. 生成计划：完整引用、FC、类型、单位/倍率、范围、步长、目标组、旧值、新值、关联约束。示例数值仅演示编码，不提供保护整定建议。
  5. 区分仅保存、修改激活组、保存后切组。若 ActSG 在过程中改变，应重新评估，不能沿用开始时的影响判断。

读取非激活组通常需选入编辑缓冲再读 SE，也会占用 SGCB。不要在后台循环切 EditSG 刷新所有组，干扰已有编辑事务。

6. 修改定值：选组 → 写入 → 校核 → 确认

教学情境：ActSG=1，修改第 2 组的一个浮点参数，暂不激活第 2 组。1.00 → 1.25 仅作通信示例，单位和适用范围另核。

  1. 选组：SelectEditSG(2) 成功后核对 EditSG。预约归当前关联；另一个客户端的 EditSG=2 不代表己方选组成功。[S4]
  2. 读基线：从 SE 取得第 2 组旧值，与变更计划核对；不能拿 SG 的第 1 组旧值代替。
  3. 写 SE：按类型写每项值，逐项检查访问结果。一条 MMS Write 传输成功不表示全部访问项成功；分批写也不是设备级原子事务。
  4. 读回 SE：核对全部变更项及关联项；浮点按设备精度和量化规则比较，保存预期值、编码值和读回值。
  5. 确认：再次检查 ActSG、预约与条件后调用 ConfirmEditSGValues。客户端检查仍有并发窗口，最终校验需设备侧联锁或项目协调。不能只观察 CnfEdit 的 true/false 认定成功。
  6. 提交后校核：检查 SGCB 和组内容。按 Ed2 预约流程，成功确认后释放编辑预约，EditSG 回到 0；该状态不能单独证明值已保存。非激活组按能力重新选择再读 SE，完成后释放；这是一次新预约。若预约失败，标记“提交已应答、保存读回待核对”。本例 ActSG 应仍为 1，运行 SG 不应因本次编辑变成第 2 组。

当前组例外：修改 ActSG 指向的组并确认时，Ed2 语义要求重新激活更新值，应核对运行 SG 及应用状态。不能因没有另写 ActSG 就认为运行值未改变。[S1、S4]

7. 切换定值组：只切换，或保存后再切换

核对目标组有效、内容已核验、切组许可；本客户端不得有未决编辑/提交，其他编辑者按项目互锁策略处理。SelectActiveSG(k) 成功后读 ActSG、LActTm 和运行 SG。读值前后再读 ActSG 可发现部分并发切组，但多次 Read 不能凭空构成原子快照，强一致性需设备机制。

ActSG=k 是组号证据，SG 是运行参数证据；两者不独自证明所有保护功能已按业务要求工作。保护功能确认、非易失保存是另行约定的验证。切组响应超时应进入结果未知状态，先查实际组号和值，不立即重试或自动回切。[S1、S6]

8. 国网与南网：差异如何落实到开发

IEC 编辑、确认、激活模型可作为共同实现基础；具体功能与流程可能受企业规范、项目版本和设备实现约束，不能只凭“国网/南网”名称硬编码。本次未取得足以逐条核验两网差异的完整适用规范原文，下表明确核验状态；不宣称已证明两网完全一致，也不把特殊流程写成全网要求。

比较项国家电网项目南方电网项目实现决策
SGCB / SG / SE 与 MMS采用相关 IEC/DL/T 服务时按共同模型；具体支持核 PICS同样先核共同模型和支持能力共用协议核心，按实际能力启用
企业规范适用版本项目适用 Q/GDW 应用模型和技术协议，待逐条核验项目适用 Q/CSG 应用模型和技术协议，待逐条核验保存编号、年份、条款与固件；未证明任一旧版本仍现行

特殊暂存区应该怎样处理

仅当适用规约明确“先写暂存区，再复制/投入目标运行区”时采用下图。复制暂存区到目标区不等于 SelectActiveSG(暂存区号)；目标运行区可能保持原区号。复制服务、目标参数、回执、组号范围及失败恢复均须有对应条款，本页不补造命令。

适配记录至少保存标准/技术协议版本、条款页码、型号/固件、普通组范围、暂存语义、整组写要求、确认/生效方式、核验对象、超时/掉电行为和实验室验证记录。按“项目＋设备＋版本”配置策略，不能只有 isNangwang 布尔开关。

练习：NumOfSG=15，能因设备位于南网就写 EditSG=31 吗？

不能。普通组按声明范围选择，特殊编号必须有适用规约和设备明确支持；出现 31 也不能自行认定可激活或代表复制提交。

9. 客户端状态机与伪代码

以下为语言无关设计示意，没有可执行网络函数。状态名为本文建议。串行化范围至少为同一设备服务器下同一 SGCB，事务绑定关联标识，不换连接继续用预约。

READY → SELECTING → EDITING → VERIFIED → CONFIRMING → COMMITTED
                                           ↓ 超时 / 断链
                                        UNCERTAIN
COMMITTED → VERIFY_SAVED → SAVED_VERIFIED
SAVED_VERIFIED → ACTIVATING → VERIFY_ACTIVE → ACTIVE_VERIFIED

edit(plan, association):
  lockLocally(plan.server, plan.sgcb)
  require verifiedProfile(plan) and authorized(plan)
  before = readSGCB()
  require validGroup(plan.group, before, profile)
  require activationEffectAccepted(plan, before.ActSG)
  selectEdit(plan.group)                // 必须收到本关联成功应答
  lease = bindReservation(association)  // 不从 EditSG 非零猜拥有者
  old = readSE(plan.verificationScope)
  require baselineMatches(old, plan)
  for batch in plan.typedWrites:
    require everyItemSucceeded(writeSE(batch))
  require equivalent(readSE(plan.verificationScope), plan.expected)
  require sameAssociationAndValidLease(lease)
  require currentConditionsAcceptable() // 设备侧仍须做最终校验
  mark(CONFIRMING)                      // 发出命令前记录阶段
  confirmEdit()
  mark(COMMITTED)
  verifySavedUsingProfile()             // 按激活/非激活选择 SG/重新选组 SE
  mark(SAVED_VERIFIED)

on failure:
  if confirmationMayHaveBeenSent or activationMayHaveBeenSent:
    mark(UNCERTAIN); reconcileByReadback(); doNotReplayAutomatically()
  else if ownReservationStillValidOnSameAssociation:
    cancelEditByProfile(); recordOriginalAndCleanupErrors()
  else:
    recordReservationLost(); reReadBeforeNewPlan()
finally:
  releaseAnyOwnedVerificationReservationByProfile()
  unlockLocally()

接口可分为 preparePlan、editGroup、verifySaved、activateGroup、verifyActive、reconcile。结果区分“编辑已校核”“提交已应答”“保存已核验”“激活已应答”“运行值已核验”“结果未知”，不要只返回 success。

日志包括事务 ID、关联标识、SGCB、目标组、开始/结束 ActSG、各项旧/新/读回值、请求阶段、invokeID、原始错误及清理结果，不记录认证秘密。本地互斥只保护本进程，外部并发仍需设备或业务协调。

10. 服务端：协议栈之外的实现职责

  1. 选组：校验组号、权限和占用；以关联为拥有者加载完整编辑副本，启动适用预约期限。未提交副本与运行值隔离。
  2. 写 SE：确认拥有者、类型、范围和权限；部分写时保留完整候选组，不把失败项静默改成默认值。
  3. 提交：再次校验跨项约束、权限与状态；协调持久化、候选组替换和运行更新，明确失败边界与应答时机。一批 Write 不等于存储事务。
  4. 激活：校验目标内容与联锁，协调应用参数、SG、ActSG 和 LActTm，避免应用读到新旧混合参数。
  5. 清理/重启：取消、断链和超时丢弃未提交副本并释放预约；掉电恢复应能识别旧版本或新版本，不能留下半组。

libiec61850 官方 API 提供激活组变更、编辑组变更和确认回调。应用仍需管理组数据、SE 装载、SG 同步与存储。内部切组接口要求先更新相应 SG 属性；确认回调返回 void，不能假设可直接将存储失败变成否定应答，应核实际栈版本与时序再设计集成。[S7]

一致提交、日志及掉电恢复结构是实现建议，不宣称协议栈自动提供数据库事务或设备已经具备这些能力。

11. 失败、取消、断链与超时恢复

阶段 / 现象解释处理
选组被拒占用、权限、非法组号或状态限制保留错误并查状态，不抢占或循环写 EditSG
多项 SE 写部分失败编辑副本可能部分改变不确认；本关联仍拥有预约时取消，修正后重新选组
提交前取消丢弃未提交编辑适用 Ed2 流程以 SelectEditSG(0) 取消；仅拥有者执行，不是提交后回滚。[S4]
预约到期 / 关联中断所有权丢失，旧 SE 不能视为有效重连先读 SGCB，再选组取新基线，不从中间继续确认。[S4、S6]
确认/切组已发，应答超时可能已执行，仅响应丢失结果未知，读实际组号和值；不自动重放或自动回切
CnfEdit 读回 false命令属性可复位，不能独自说明结果结合请求应答和保存/运行读回，不无限等待 true
确认后重启恢复旧值保存时机或实现不符预期核 PIXIT 的持久化承诺，在隔离测试环境验证
读回不一致组、FC、类型、量化、并发或设备约束按引用→组→类型/单位→响应→状态核查，不靠放宽容差掩盖问题

MMS 每项访问错误、服务级错误、关联错误与本地超时分层保存，不全部解释成“越限”。具体错误码和 ACSI 映射按采用的 8-1 与 SDK 枚举核对。

练习：确认应答丢失但 SG 已读到新值，能立刻重发 CnfEdit 吗？

不能。先核对组号、目标值与并发情况，再恢复业务状态；预约可能已释放。若无法消除歧义，保留结果未知，进入约定恢复流程。

12. 联调用例与通过条件

以下用于独立测试环境。UCA 服务端 sSg 用例覆盖编辑、切组、断链、预约等协议行为，本表补充应用集成问题，不能代替正式一致性测试。[S6]

用例应观察的结果
不支持 SGEdit / 普通 SP 参数正确识别能力，不误走 SGCB
编辑非激活组并确认重选读回已保存值；ActSG 与运行 SG 不因编辑改变
编辑激活组并确认按版次/设备规则更新运行值，提示与记录正确
只切组 / 保存后切组核对 ActSG、SG、辅助 LActTm，保存与激活结果分开
