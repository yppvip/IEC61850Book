对象引用：语法、SCD 追踪与工程使用

从一个信号名，找到对象、类型与通信配置；用同一条证据链完成开发和调试复习。

先看结论与查阅路线

对象引用（ObjectReference）是 IEC 61850 信息模型中定位某个实例的路径。定位到数据属性时，也称数据属性引用。工程口语中的“信号引用”“点名”应结合工具上下文理解；ObjectName 只是某一层的局部名称。对象引用不是 IP 地址、XML XPath、ASN.1 OID 或单独的类型模板 ID。

上级：数据模型 → IED 与数据模型。建议先认识 LD、LN、DO、DA，再读本页；随后进入 SCD 阅读工具箱和数据集与控制块。页内目录可直接复习。

拿到一个信号名拆解 PROT/PDIS1.Str.general确认引用到哪一层LD、LN、DO、属性、数据集和控制块反查 SCD 配置实例字段 → 类型链 → FCDA解决开发与调试问题掌握范围、排障顺序与自检

快速复习：完整名与 FC · 测量类型链 · FCD / FCDA 粒度 · MMS / SDK 表示 · 发布与订阅 · 分层排障 · 自检答案 · 来源与证据

本文是原创静态技术讲解。依据 IEC 61850-7-2 的引用模型、7-3/7-4 的数据语义、6 的 SCL 组织及 8-1 的 MMS 映射分别解释。引用字符数、数组和服务细节需核对适用版次，不能把早期版限制当作跨版次全集。所有 XML 均为从指定 SCD 重构、脱敏并裁剪的教学片段，不是标准原文、设备手册或可投产工程。

2. 语法、层级与使用位置

常用层级表示（非完整的所有服务对象语法）：
LDRef             = LDName
LNRef             = LDName/LNName
DataRef           = LDName/LNName.DO[.SDO...]
属性引用           = LDName/LNName.DO[.SDO...].DA[.BDA...]
LNName            = prefix + lnClass + inst

永久数据集引用      = LDName/LNName.DataSetName
控制块抽象引用      = LDName/LNName.ControlBlockName

/ 分隔 LD 和 LN；. 分隔后续层级。方括号、占位名和省略号表示语法说明，不是要输入的字符。名称区分大小写。LLN0 是专门的管理逻辑节点名，不再额外拼上一个 0。必须结合对象类别判断 LN 下的名字指 DO、DataSet 还是控制块，不能仅按点的数量识别。

层级 / 形式教学例子典型用途与边界
LDRefDemoIED_1MEAS浏览 LD 下的 LN。它本身不是一个布尔或模拟量。
LNRefDemoIED_1MEAS/GOGGIO1定位节点，查询数据或其他对象目录。
DO / SDO 引用DemoIED_1MEAS/GOGGIO1.AnIn1定位整个数据对象；按服务和 FC 读取适用属性组，不承诺一次返回所有 FC。
结构 DA 引用DemoIED_1MEAS/GOGGIO1.AnIn1.mag这里 mag 是结构属性；需查看 DAType 及返回结构。
叶子 BDA 引用DemoIED_1MEAS/GOGGIO1.AnIn1.mag.f定位浮点叶子；所属 FC 从上层 DA mag 取得。
永久 DataSet 引用DemoIED_1MEAS/LLN0.DemoSet_1定位有序成员集合，读目录/成员值或供控制块关联。
控制块抽象引用DemoIED_1MEAS/LLN0.DemoGoCB_1定位发布控制对象；协议字段与 SDK 具体格式另核对，见第 7 节。

不能把每个点后的名称都称为 DA。测量对象可能经过 DO → SDO → DA → BDA，例如教学路径 MMXU1.A.phsA.cVal.mag.f 中，phsA 是 SDO，cVal 是结构 DA，mag/f 是结构分量。SDO 通过 DOType 追踪，BDA 通过 DAType 追踪。层级身份由模板决定。

数组引用还涉及元素下标及适用版次的访问规则，常见引用记法含 (n)；SCL 的 count、ix 与 SDK 的数组访问参数应分别处理。不要删除下标、假定一律从 1 计数，或把下标当成 LN 实例号。本页提取脚本对数组显式报未支持，不假装完成数组映射。关联专用数据集还存在 @DataSetName 表达；@ldInst/... 是特定 SCL 对象引用值的 IED 相对形式，均不能当作任意接口中的绝对 DO 路径。详见公共类型与作用域。

3. 完整 LDName、LNName 与 FC

通常的产品命名方式：
IED@name = DemoIED_1
LDevice@inst = MEAS
LDName = DemoIED_1MEAS                 （直接拼接，无额外斜杠）

LN@prefix = GO ; LN@lnClass = GGIO ; LN@inst = 1
LNName = GOGGIO1

对象引用 = DemoIED_1MEAS/GOGGIO1.AnIn1.mag.f
FC       = MX

若适用版本、能力与工程采用显式 LDevice@ldName，则通信可见 LDName 按该字段确定，不再机械拼接 IED 名。本参考 SCD 没有配置 ldName，因此本页按通常产品命名重建路径；实际设备目录仍应与加载的工程版本核对。不要试图从任意 LDName 字符串反向猜出 IED 名与 ldInst 的分界，应使用工程字段建立索引。

FC（Functional Constraint，功能约束）把数据属性按用途分组，常用 ST 状态、MX 测量、CF 配置、CO 控制、DC 描述、SG/SE 定值组/编辑视图。FC 不是数据类型，也不单独授予读写权限；fc=SV 表示取代属性组，与采样值协议 SV 不同。

软件应保留 服务器/接入点上下文 + ObjectReference + FC，并关联工程修订、类型与业务绑定。相同引用文本可能出现在不同设备连接或项目版本中；只有一个字符串不足以成为跨项目测点唯一键。

4. SCD 怎样组织对象，怎样提取

  1. 读取根版本和命名空间。使用 XML 解析器绑定 http://www.iec.ch/61850/2003/SCL，不能用文件中的 namespace 前缀拼死 XPath。相同命名空间字符串不代表全部版次相同。
  2. 定位 IED / AP / Server / LD。数据集 FCDA 的 ldInst 定位本 IED 中的数据源 LD；ExtRef 用 iedName 指向源 IED。若多个 AP 暴露同一 Server，须结合 ServerAt 和设备模型处理，本页脚本仅处理所选直接 Server 实例。
  3. 定位 LN。按 prefix、lnClass、lnInst 联合查找，对应 LN 上的 prefix、lnClass、inst；LLN0 单独处理。不要把 LN 的 inst 与 FCDA 的 lnInst 属性名混用。
  4. 沿模板核对路径。用 LN@lnType 找 LNodeType@id，再按 DO@name 查 DOType。doName 可包含点分隔的 SDO；daName 从顶层 DA 继续，结构 bType=Struct 时沿 DAType/BDA 展开，枚举沿 EnumType 确认编码。
  5. 核对 FC 和粒度。叶子 BDA 继承所属 DA 的 FC；若没有 daName，按 FCD 语义检查该 FC 下的属性组，不自行补为 stVal 或 general。
  6. 组装并保存证据。输出规范化路径、FC、基础类型、CDC、源行、所属服务器和工程哈希；将“找不到”“多候选”“类型冲突”“当前提取器不支持”分别记录。
提取流程（教学伪代码，省略版次细节）：
source = resolve_IED_and_server(context, fields)
ld     = unique_LDevice(source, inst=fields.ldInst)
ln     = unique_LN(ld, fields.prefix, fields.lnClass, fields.lnInst)
types  = follow_types(ln.lnType, fields.doName, fields.daName)
check_FC(types.owning_DA, fields.fc)
LDName = configured_ldName_or_product_name(source.IED.name, ld)
return {server_context, ObjectReference, FC, type, source_location}
DOI/SDI/DAI 不是完整的数据模型目录。它们承载实例配置；未显式出现 DAI，不代表 DA 不存在。应先从类型模板建立模型，再读取实例配置覆盖或初始值。DAI/Val 不能当作实时运行值；lnType、DOType@id 和 DAType@id 是类型引用，不拼入运行对象路径。

本专题的可复现提取器位于项目 scripts/build_object_reference.py，网页运行时只读本地静态内容，不读取源 SCD。该脚本检查所选普通路径、唯一性和类型/FC，不实现完整 SCL 校验、ServerAt 解析或数组访问。

5. 实际例子：AnIn1.mag.f 的完整类型链

从指定 SCD 中选择第一个满足 prefix=GO、lnClass=GGIO、doName=AnIn1、daName=mag.f 且所属节点有 GSEControl 的数据集成员。保留标准技术名称、字段与源行；IED、类型 ID、数据集、控制块和 AP 名统一替换为 Demo 别名，其余非必要内容省略。

{{MEASUREMENT}}

本例 mag 是 DA，f 是 BDA，FC=MX 来自 mag，叶子类型为 FLOAT32。q/t 属于 AnIn1，不能拼成 mag.f.q。这个 FCDA 只选择 mag.f，不会自动把 AnIn1.q 和 AnIn1.t 一起加入数据集；是否另有品质/时标成员须看完整集合。不能从 AnIn1 或 prefix=GO 推断它代表哪一路电流、电压或联锁量，单位和实际测点应另查实例及工程绑定。

8. 从信号走到控制块与订阅

  1. 由属性反查 FCDA。既查精确 daName，也检查同一 DO/FC 的 FCD 或结构成员是否包含该属性；保留全部候选。
  2. 定位数据集拥有者。记录包含 DataSet 的 LN/LD；FCDA 的 ldInst 是数据源 LD，不保证等于数据集拥有者 LD。
  3. 查同一拥有者下引用 datSet 的控制块。同一信号可能进入多个数据集、报告、日志或 GOOSE，不能默认一对一。
  4. 按服务查通信配置。GOOSE 使用源 IED、AP、控制块所在 LD 和 GSE@cbName 关联；SV 查对应 SMV。MMS/报告则关联服务器接入点、地址与客户端使用状态。
  5. 反查接收端 ExtRef。按源 IED、LD、LN、DO、DA 和适用的 serviceType/src* 字段缩小候选；配置缺少控制块信息时记录多义性，不根据 MAC/APPID 认定业务。
{{EXTREF}}

这条 ExtRef 描述源端 XCBR1.Pos.stVal，而拥有 Inputs 的 LN 是接收端。intAddr 是实现相关的接收内部绑定，本页替换为 DemoInternalBinding；即使原值看起来像对象路径，也不能直接当成标准源引用。ExtRef 没有 fc 字段，源属性的 FC 应沿类型或匹配的发布成员确认。

有源对象不代表已进入数据集，有发布控制块不代表本文件一定声明接收订阅；有 ExtRef 也不能证明订阅已下载或运行生效。网页提供静态追踪方法，不连接装置或提供报文解析功能。

9. 开发人员与调试人员掌握清单

能力软件开发人员应做到现场调试人员应做到
定位与语法保留大小写、服务器作用域、完整 LDName、FC；不硬编码固定层级。能把工具显示的短名核对为实际设备目录中的完整引用。
类型与语义解析 DO/SDO、DA/BDA、枚举与基础类型；不把所有 ST 当 BOOLEAN。说明启动、动作、位置反馈的区别，查明实际信号绑定。

质量与时间正确关联 q/t、源时间与接收时间，保留过期、坏品质、测试/取代信息。不以“有值”判定可用，不把接收时间当作源事件时间。

完成标准：面对陌生信号，能交付一条可复核记录：服务器上下文、完整引用、FC、类型/CDC、q/t 归属、数据集与成员粒度、控制块候选、工程版本和未决问题。无需背下所有节点名称，但必须能沿模板查明。

随手记录卡：连接/工程版本 → ObjectReference + FC → 类型 → 数据来源/业务绑定 → DataSet/成员位置 → 控制块/订阅 → 当前值、q、t → 尚缺证据。继续读应用数据契约与工程证据核查。

10. 常见错误与排查顺序

现象优先核查
对象不存在服务器/AP 是否正确 → PROT 是否只是 ldInst → prefix/大小写/实例号 → 实际目录与加载版本 → 类型路径。
路径看起来正确但读取失败FC、服务支持、访问视窗/权限与设备状态；单看错误文本不能断定根因。
SCD 中搜不到 general 的 DAI先查 LN 的 lnType 和 DOType；实例没有显式配置该成员不等于类型不存在。
收到一个结构而不是布尔值FCDA 是否没有 daName，或选取了结构 DA；按模板解释，不能随意取第一个元素。
报告/GOOSE 信号对应错位数据集修订、成员顺序、FCD 展开及报告 inclusion；不要按名称排序或固定叶子偏移。
值在变化，品质/时标没更新q/t 是否单独入集或包含在结构中；触发选项、关联关系和接收策略是否正确。
同一属性找到多个控制块保留候选并按服务、拥有者和接收声明缩小范围；不能任选一条充当唯一来源。

复习顺序：连接与版本 → 完整名 → 类型路径 → FC → 数据集粒度 → 控制块/订阅 → 值、品质和时间 → 业务与现场证据。

11. 用五道题自检

PROT/PDIS1.Str.general 可以直接作为任何设备上的读取地址吗？

不可以。先确认 PROT 是否完整 LDName、连接的服务器、该 PDIS 实例及类型是否存在，再确定 FC=ST 与接口表达。本参考 SCD 没有 PDIS。

mag.f 中哪一段提供 FC？q/t 应该挂在哪里？

实际例子中 mag 是 DA，提供 MX；f 是 BDA。q/t 是 AnIn1 的同级 DA，路径为 AnIn1.q / AnIn1.t，不是 mag.f.q。

没有 daName 的 Str、FC=ST 成员等于 Str.general 吗？

不等于。它是 FCD，本例选取 general、dirGeneral、q、t 的结构；不包含 DC 下的 dU。结构和顺序按实际类型及映射确认。

ExtRef.intAddr 看起来像路径，能拿来定位发布端吗？

不能只凭形状判断。发布端由 iedName/ldInst/prefix/lnClass/lnInst/doName/daName 等描述；intAddr 表示接收内部绑定，具体语义依实现。

Str.general=true 且品质良好，能证明断路器已经跳闸吗？

不能。它只说明对应启动信息，仍需动作、出口、控制或执行回路及位置反馈的证据。
